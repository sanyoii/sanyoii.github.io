這一輪測了什麼？

每個 Run ID 都連到它收錄的 Test Cases。頁面顯示受測版本、檢查內容與預期結果，讓人不用閱讀 JSON 就能了解測試範圍。

這是 sanitized Run 記錄，沒有逐項 raw output。現有資料只足以確認 Run 的整體結果與當時收錄的 Test Cases；原始 JUnit／人工檢查檔目前不在公開頁，也不會假裝成可下載的結果。

Order book（9 個 Test Cases）
Test Case優先級檢查內容預期結果
OB-001P1建立未排序的 order book，讀取最佳買價與賣價。回傳最高買價、最低賣價，並保留 Decimal 精度。
OB-002P0套用連續更新，包含新增與數量歸零的價位。新增價位、刪除零數量價位，update ID 更新為 101。
OB-003P0把過期 event 套用到現有 order book。回傳 False，update ID 與可見價位都不變。
OB-004P0套用中間有缺口的 event。在改動資料前拋出 SequenceGapError。
OB-005P0用買價高於賣價的 crossed snapshot 建立 order book。拋出 MarketInvariantError，並保留買賣價資訊。
OB-006P0同步 snapshot、過期 event 與連續 event。略過過期 event，連續套用到 update 102。
OB-007P0以零價格、零數量及負數量建立 snapshot。每一組無效資料都拋出 MarketInvariantError。
OB-008P0對有效 order book 套用負數量更新。拋出 MarketInvariantError；零仍只代表刪除價位。
OB-009P0用缺少 bids 或 asks 的 snapshot 建立 order book。因市場兩側都不可為空而拋出 MarketInvariantError。
REST contract（9 個 Test Cases）
Test Case優先級檢查內容預期結果
REST-001P1用小寫 symbol 取得 bookTicker，檢查 request 與回傳值。送出 BTCUSDT，回傳標準化 symbol 與 Decimal 數值。
REST-002P0處理 bid 高於 ask 的 ticker。以 RestContractError 拒絕 crossed market data。
REST-003P1以 btcusdt、limit 5 取得 depth。送出標準化參數，驗證 snapshot 後才回傳。
REST-004P1要求不存在的 symbol，檢查錯誤內容。保留 HTTP 400、exchange code -1121 與訊息。
REST-005P1取得單一 symbol 的 exchangeInfo。回傳 BTCUSDT、TRADING、PRICE_FILTER 與 LOT_SIZE。
REST-006P0處理 bid quantity 為零的 ticker。以 RestContractError 拒絕非正數值。
REST-007P1處理 exchangeInfo 回傳零個或兩個 symbol。除非恰好只有一個 symbol，否則拋出 RestContractError。
REST-008P1處理缺少欄位或不是 object 的 ticker payload。拋出 RestContractError，並提供穩定的 schema 訊息。
REST-009P1模擬 REST transport timeout。保留 httpx.ReadTimeout 類型與原始訊息。
WebSocket contract（12 個 Test Cases）
Test Case優先級檢查內容預期結果
WS-001P1訂閱一筆 ticker，檢查控制訊息與 event。完成訂閱、驗證、取消訂閱，且 request ID 1／2 對應正確。
WS-002P0接收 update ID 102 後再收到 101。update ID 倒退時拋出 WebSocketContractError。
WS-003P1預期 BTCUSDT，實際收到 ETHUSDT。拒絕錯誤 symbol，訊息包含預期值與實際值。
WS-004P0接收 quantity 為零的 event。拒絕非正數的 price 或 quantity。
WS-005P0接收 bid 高於 ask 的 event。拒絕 crossed market data。
WS-006P1預期 acknowledgement ID 1，實際收到 99。拒絕不相符的 acknowledgement。
WS-007P1取消訂閱後，acknowledgement 前仍收到 market event。忽略途中 event，等到正確 acknowledgement 後完成。
WS-008P0同步 REST snapshot 100 與 stale／continuous events。回傳 update 102 的同步 order book，買賣價位符合預期。
WS-009P1用 0.01 秒 timeout 等待緩慢連線。在設定的時間內拋出 TimeoutError。
WS-010P1訂閱後接收格式錯誤的 JSON。拋出 WebSocketContractError，訊息指出 JSON 無效。
WS-011P1訂閱後接收 JSON array。因 protocol payload 必須是 object 而拒絕。
WS-012P1acknowledgement 正確，但 ticker 缺少 A 欄位。拋出 WebSocketContractError，並提供穩定的 schema 訊息。
Documentation contract（4 個 Test Cases）
